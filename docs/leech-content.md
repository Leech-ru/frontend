# Раздел о пиявках: контент и CMS

## Решение

Раздел `/leech` хранит длинные материалы в markdown-файлах:

- `content/leech/*.md` — русская версия;
- `content/en/leech/*.md` — английская версия.

Порядок разделов, подписи навигации, SEO-описания по умолчанию, иконки и
изображения задаются в TypeScript-manifest:

- `src/entities/leech-docs/model/docs.ts`.

Такой гибрид проще полноценной headless CMS: контент остается в git,
проходит ревью через PR, хорошо подходит для Angular SSR/prerender и не требует
отдельной базы данных, API, кеширования и секретов.

## Почему не отдельная headless CMS

Для текущей задачи нужно поддерживать небольшой справочный раздел из нескольких
статей. Headless CMS даст роли, workflow и медиа-библиотеку, но добавит
runtime-зависимость, авторизацию, инвалидацию кеша и отдельную i18n-модель.
Это оправдано позже, если появятся десятки авторов, расписание публикаций,
черновики и частые изменения без PR.

## Decap CMS

В проект добавлен легкий git-based редактор Decap CMS:

- UI: `/cms/`;
- конфигурация: `public/config.yml`;
- медиа: `public/images/leech`.

Decap редактирует markdown-файлы и коммитит изменения в GitHub. Новую страницу
можно создать через CMS, но чтобы она появилась в навигации сайта, нужно также
добавить ее slug в `LEECH_DOCS`.

## Локальный запуск редактора

1. Запустить Angular:

```bash
npm run serve:ru
```

2. В отдельном терминале запустить локальный Decap proxy:

```bash
npx decap-server
```

3. Открыть:

```text
http://localhost:4200/cms/
```

## Продакшен

Для production-редактирования нужен GitHub OAuth backend для Decap CMS. Текущий
`public/config.yml` указывает `repo: Leech-ru/frontend` и `branch: main`.
Пользователь редактора должен иметь доступ на запись в репозиторий.

## Правила контента

- Первый `#` в markdown используется как редакционный заголовок и не
  дублируется в статье: страница показывает заголовок в hero-блоке.
- `##` автоматически попадают в содержание справа на desktop.
- HTML внутри markdown намеренно вырезается при рендере.
- Ссылки допускаются только `https`, `http`, `mailto`, `tel`, относительные
  пути и якоря.
- Длинные пользовательские строки должны оставаться в markdown, короткие UI
  подписи — в Angular-шаблонах через `i18n` или в TS через `$localize`.
